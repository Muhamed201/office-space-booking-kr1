# 10 — Банк задач: Java + ООП + Коллекции + БД/JDBC

Материал охватывает презентацию «Программирование корпоративных систем» от начала до слайда
**«Контрольная точка №2»** (стр. 151) включительно: блок **01 — Повторение Java** (типы, ООП,
коллекции, исключения) и блок **02 — Работа с базами данных** (проектирование БД, SQL, JDBC,
транзакции). Материал JavaFX (блок 03, «Контрольная точка №3») сюда не входит.

## Как пользоваться файлом

- 17 тем, в каждой — 15 задач **базового** уровня и 15 задач **продвинутого** уровня.
- Темы идут в порядке презентации, кроме тем по коллекциям — они специально сдвинуты ниже
  (после ООП и исключений), чтобы не мешать в кучу базовые типы и структуры данных.
- Каждая задача — отдельное упражнение, решать по одной. Условия сформулированы так, чтобы
  результат можно было проверить по входу/выходу или по описанному поведению.
- Решения не приложены намеренно — это пул задач для самостоятельной практики перед защитой.

## Обязательное правило для каждой задачи

Задача не считается решённой, если класс просто написан и лежит без дела — по требованию курса
результат нужно **показать в работающей программе**:

1. Пишете `class Main { public static void main(String[] args) { ... } }` (или отдельный метод
   `main` в одном из классов задачи).
2. В `main` создаёте объект(ы), вызываете описанные в условии методы и печатаете результат через
   `System.out.println(...)`, чтобы его можно было увидеть на экране и сверить с ожидаемым.
3. **Если в задаче фигурирует абстрактный класс или интерфейс** (условие говорит «создайте
   абстрактный класс X», «опишите интерфейс Y» и т. п.) — этого недостаточно, обязательно нужно:
   - реализовать **не менее двух** конкретных подклассов/реализаций с именами из условия (если они
     заданы) или своими, но осмысленными;
   - в каждом подклассе переопределить **все** абстрактные методы **разной, содержательно
     отличающейся** логикой — не пустыми заглушками вида `return null;` или одинаковым кодом,
     скопированным между подклассами;
   - в `main` создать по объекту каждого подкласса и вызвать на них **один и тот же** метод
     базового типа (например, через переменную типа `Shape shape = new Circle(...)`), чтобы на
     экране было видно разное поведение — это и есть демонстрация полиморфизма, а не просто
     компилирующийся код.
4. Если в задаче явно не названы имена подклассов — придумайте минимум два своих, подходящих по
   смыслу к предметной области условия.

Дальше в тексте задач это правило не повторяется каждый раз отдельными словами — читайте его как
часть условия любой задачи, где встречаются слова «абстрактный класс», «интерфейс», «подкласс»,
«наследник», «реализация».

# Часть 1. Базовый уровень

## 1. Примитивные типы, операторы, приведение типов

1. Объявите переменные всех восьми примитивных типов (`byte`, `short`, `int`, `long`, `float`,
   `double`, `char`, `boolean`) с осмысленными значениями и выведите каждую в формате
   `тип = значение`.
2. Сложите `byte`-переменную со значением `120` и `byte`-переменную со значением `10` без явного
   приведения типов; объясните комментарием, почему код не компилируется, и исправьте явным
   приведением `(byte)`.
3. Прибавьте `1` к `Integer.MAX_VALUE`, выведите результат и объясните комментарием, почему
   получилось отрицательное число.
4. Напишите метод `intPart(double x)`, который возвращает целую часть числа без округления через
   `(int) x`, и отдельно метод `rounded(double x)` — с округлением через `Math.round`. Сравните
   результаты на числе `3.7` и на `-3.7`.
5. Продемонстрируйте расширяющее преобразование (widening) `int → long → float → double` на одной
   переменной: печатайте значение и его тип после каждого шага через `instanceof` или комментарий.
6. Посчитайте площадь круга радиусом `7` для радиуса типа `float` и для радиуса типа `double`;
   выведите оба результата с 10 знаками после запятой и объясните разницу в точности.
7. Напишите метод `nextLetter(char c)`, который возвращает следующую букву латинского алфавита
   через арифметику с `char` (без `switch`), и обработайте случай `c == 'z'` как переход к `'a'`.
8. Сравните два числа типа `double` (`0.1 + 0.2` и `0.3`) оператором `==` и через сравнение с
   допуском `epsilon = 1e-9`; выведите оба результата и объясните разницу.
9. Реализуйте целочисленный калькулятор с операциями `+`, `-`, `*`, `/` для `int`, где деление на
   ноль не бросает `ArithmeticException`, а выводит сообщение `"Деление на ноль недопустимо"`.
10. Напишите метод `fitsInInt(long value)`, который без явного приведения определяет, поместится
    ли `long`-значение в `int`, сравнивая его с `Integer.MIN_VALUE` и `Integer.MAX_VALUE`.
11. Реализуйте обмен значений двух переменных типа `int` через побитовый XOR, без третьей
    переменной, и проверьте на паре `(5, 12)`.
12. Посчитайте факториал числа для типов `int` и `long`; определите опытным путём, при каком
    минимальном `n` факториал переполняет `int`, и выведите это `n`.
13. Реализуйте перевод температуры между шкалами Цельсия, Фаренгейта и Кельвина тремя методами
    (`double`), проверив на значении `100.0` (кипение воды в Цельсиях).
14. Напишите метод `selectAndScale(boolean flag, int a, int b, int factor)`, который тернарным
    оператором выбирает `a` при `flag == true` или `b` при `flag == false`, а затем умножает
    результат на `factor`.
15. Реализуйте метод `isLeapYear(int year)` (високосный год: делится на 4, но не на 100, кроме
    случаев деления на 400) и проверьте его на годах `1900`, `2000`, `2024`, `2023`.

## 2. Строки и обёртки (String, Integer, char/Unicode)

1. Напишите метод `reverse(String s)`, разворачивающий строку без использования
   `StringBuilder.reverse()`, только циклом и индексами.
2. Объясните на примере (в коде и комментарии) разницу между `String a = "hi"` и
   `String b = new String("hi")` — сравните `a == b`, `a.equals(b)` и результат для двух литералов
   `"hi" == "hi"`.
3. Напишите метод `countVowels(String s)`, считающий количество гласных букв (`а, е, ё, и, о, у,
   ы, э, ю, я` для кириллицы или `a, e, i, o, u` для латиницы — выберите один алфавит и укажите его
   в условии) без учёта регистра.
4. Реализуйте метод `isPalindrome(String s)`, который перед проверкой убирает пробелы и приводит
   строку к одному регистру; проверьте на строке `"А роза упала на лапу Азора"`.
5. Напишите метод `parseIntSafe(String s)`, который пытается превратить строку в `int` через
   `Integer.parseInt`, ловит `NumberFormatException` и возвращает `Optional<Integer>` вместо
   исключения.
6. Продемонстрируйте автоупаковку (autoboxing) и её ловушку: сравните `Integer a = 127; Integer b
   = 127; a == b` и `Integer c = 200; Integer d = 200; c == d`; объясните разницу через кэш
   `Integer` (`-128..127`).
7. Напишите метод `wordCount(String text)`, считающий количество слов в строке, разделённых одним
   или несколькими пробелами (используйте `String.trim()` и `split("\\s+")`).
8. Реализуйте метод `toTitleCase(String s)`, делающий первую букву каждого слова заглавной, а
   остальные строчными, без использования сторонних библиотек.
9. Напишите метод `charFrequency(String s)`, возвращающий `Map<Character, Integer>` с количеством
   вхождений каждого символа в строке (без учёта пробелов).
10. Продемонстрируйте неизменяемость (`immutable`) строк: создайте `String s = "abc"`, вызовите
    `s.concat("def")` без сохранения результата и выведите `s`, объяснив, почему он не изменился.
11. Напишите метод `unicodeCode(char c)`, выводящий числовой Unicode-код символа, и обратный метод
    `fromCode(int code)`, возвращающий символ по коду.
12. Реализуйте метод `removeDuplicateChars(String s)`, убирающий повторяющиеся символы, сохраняя
    порядок первого появления, без использования `Set`.
13. Напишите метод `formatMoney(int kopecks)`, превращающий количество копеек в строку вида
    `"123.45 руб."`, используя только арифметику и `String.format`.
14. Сравните производительность конкатенации строк в цикле из 10 000 итераций через `+` и через
    `StringBuilder.append()`: измерьте время `System.nanoTime()` до и после каждого варианта и
    выведите разницу.
15. Напишите метод `isValidIdentifier(String s)`, проверяющий, может ли строка быть именем
    Java-переменной: первый символ — буква или `_`, остальные — буквы, цифры или `_`, строка не
    пуста.

14. Реализуйте вложенные циклы, печатающие треугольник из звёздочек высотой `n` (задайте `n` через

## 4. ООП: классы, объекты, конструкторы

1. Опишите класс `Person` с полями `name` (String), `age` (int) и двумя конструкторами: полным (с
   обоими полями) и коротким (только `name`, `age` по умолчанию `0`). В `main` создайте по одному
   объекту через каждый конструктор и выведите оба объекта на экран.
2. Добавьте в класс `Person` из задачи 1 метод `introduce()`, возвращающий строку `"Меня зовут
   <имя>, мне <возраст> лет"`. В `main` создайте три объекта `Person` с разными данными, вызовите
   `introduce()` у каждого и напечатайте результат.
3. Опишите класс `Rectangle` с полями `width`, `height` (double), методами `area()` и
   `perimeter()`. В `main` создайте один `Rectangle` через конструктор без параметров (сторона `1`)
   и один через конструктор с двумя параметрами; для обоих выведите `area()` и `perimeter()`.
4. Реализуйте класс `Point` с полями `x`, `y` (int) и методом `distanceTo(Point other)`,
   вычисляющим евклидово расстояние между двумя точками. В `main` создайте три точки, посчитайте и
   выведите расстояние между каждой парой.
5. Опишите класс `Counter` со статическим полем `totalCreated` (`static` — общее на весь класс, а
   не на один объект) и конструктором, увеличивающим это поле при каждом создании объекта. В `main`
   создайте пять объектов `Counter` и после этого выведите `Counter.totalCreated`, обратившись к
   полю через имя класса, а не через объект.
6. Реализуйте класс `Book` с полями `title`, `author`, `year` и переопределённым методом
   `toString()`, возвращающим строку вида `"Название (Автор, Год)"`. В `main` создайте `List<Book>`
   из четырёх книг и выведите список циклом `for-each`, чтобы для каждой книги напечаталась строка
   из `toString()`.
7. Создайте класс `BankAccount` с полем `balance` (double, приватное) и конструктором, принимающим
   начальный баланс с проверкой, что он не отрицателен (иначе — `balance = 0`, без исключения на
   этом шаге). В `main` создайте `BankAccount` с отрицательным начальным балансом и `BankAccount` с
   обычным балансом, выведите итоговый `balance` у обоих, чтобы показать, что проверка сработала.
8. Опишите класс `Car` с полями `brand`, `model`, `speed` и методом `accelerate(int delta)`,
   увеличивающим скорость. Реализуйте три конструктора: полный `(brand, model, speed)`, короткий
   `(brand, model)` со `speed = 0` через вызов `this(brand, model, 0)`, и совсем короткий `(brand)`
   со `model = "unknown"` через `this(brand, "unknown")`. В `main` создайте по одному объекту через
   каждый конструктор, вызовите `accelerate(10)` у всех трёх и выведите их поля.
9. Реализуйте класс `Time` с полями `hours`, `minutes`, `seconds` и методом `addSeconds(int sec)`,
   корректно переносящим переполнение в минуты и часы (60 секунд → +1 минута, 60 минут → +1 час). В

10. Опишите класс `Student` с полями `name` и `grades` (`List<Integer>`, инициализируется прямо в

## Дополнительно: специальные модификаторы

Эти модификаторы не образуют отдельную большую тему с 15 задачами, но их обязательно спрашивают на
защите — разберите их отдельно, до перехода к исключениям.

1. Опишите класс `Config` с полем `public static final int MAX_USERS = 100;`. В `main` обратитесь к
   нему как `Config.MAX_USERS` (без создания объекта) и объясните комментарием, что здесь три
   модификатора и что даёт каждый: `static` — поле общее на класс, а не на объект; `final` —
   значение задаётся один раз и не может измениться; `public` — видно отовсюду.
2. Опишите класс `Base` с методом `public final void criticalStep() { ... }`. Попробуйте написать
   подкласс, переопределяющий `criticalStep()`, и объясните комментарием, почему это не
   компилируется — `final` у метода запрещает переопределение в наследниках.
3. Опишите класс `Base`, объявленный как `final class Base { ... }`. Попробуйте написать `class
   Derived extends Base { ... }` и объясните комментарием ошибку компиляции — `final` у класса
   запрещает наследование от него вообще.
4. Создайте на одном уровне (не вложенные) два класса `PublicClass` (модификатор `public`) и
   `PackageClass` (без модификатора — package-private). В `main` (в том же пакете) создайте объекты
   обоих и объясните комментарием, что внешний класс верхнего уровня может быть только `public` или
   package-private — модификаторы `private` и `protected` для него недопустимы, они разрешены
   только у **вложенных** (nested) классов.
5. Опишите класс `Outer` с приватным вложенным классом `private class Inner { ... }`. Покажите в
   `main` (в том же файле, через метод `Outer`, создающий `Inner` изнутри), что `Inner` не виден
   снаружи класса `Outer`, и объясните, почему `private`/`protected` у класса вообще возможны только
